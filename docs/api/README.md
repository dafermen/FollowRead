# API Documentation

OpenAPI generated by FastAPI at `/docs` is the executable contract reference.

## Public catalog

### `GET /catalog`

Returns `items`, `total`, `limit` and `offset`. Accepts:

- `language`: `en` or `es`;
- `content_type`: `story`, `article`, `book` or `lesson`;
- `audience`: `children`, `teenager`, `adult` or `all`;
- `reading_level`: level code;
- `category`: category slug;
- `limit`: 1 to 100;
- `offset`: non-negative integer.

Each summary includes version, languages, checksum, package URL and minimum app version.
The list only exposes active releases with version `published` and full package.

### `GET /catalog/{slug}`

Returns the summary plus translations, chapters and ordered paragraphs. A nonexistent, draft,
inactive or incomplete slug responds as `content.not_found`.

### `GET /catalog/{slug}/reader-package`

Returns the verifiable package used by Reader. Each chapter may include `image_uri` and
`image_alt_text`; both are `null` when a specific illustration does not exist and the app then uses
`cover_uri`/`cover_alt_text`. Editorial position 0 identifies the cover and
positions 1..N the chapter images.

Stable errors are documented at `docs/api/ERRORS.md`. Authentication and administrative endpoints
remain outside this phase.

## Operation

- `GET /health` indicates the process is responsive; it does not probe dependencies.
- `GET /ready` checks SQLite and returns 200 `ready` or 503 `not_ready`.
- Every response includes `X-Request-ID`. A safe incoming value is preserved; any
  missing or invalid value is replaced.
- Logs are single-line JSON with UTC time, level, event, request ID, method, path without query,
  status and duration. They do not include bodies, parameters, tokens or traces in the response.
- An unexpected error returns `internal_error` with the request ID and logs the trace only in logs.

OpenAPI must contain `/health`, `/ready`, `/catalog` and `/catalog/{slug}`, in addition to the success and error schemas. This topology is checked automatically.
